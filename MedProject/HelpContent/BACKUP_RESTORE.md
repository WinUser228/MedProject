# Резервное копирование и восстановление базы данных

База данных приложения — это файл **`HospitalStatistics.db`** в **каталоге данных пользователя** (не рядом с установленной программой). В нём хранятся все введённые данные: отделения, койки, движение пациентов и т.д.

**Где искать файл:**
- **Linux:** `~/.local/share/MedProject/HospitalStatistics.db`
- **Windows:** `%LOCALAPPDATA%\MedProject\HospitalStatistics.db`

Кнопки резервного копирования в программе работают с этим файлом автоматически — знать путь вручную нужно только для копирования без приложения или для переноса на другой компьютер.

Регулярное резервное копирование защищает от потери данных при сбое диска, случайном удалении или переустановке системы.

## Создание резервной копии (через программу)

1. Откройте раздел **«Справка»** (боковое меню или **Ctrl+3**).
2. В списке слева выберите тему **«Резервное копирование БД»**.
3. Нажмите кнопку **«Создать резервную копию БД»**.
4. Укажите **папку**, куда сохранить файл (например, флешку, сетевой диск или отдельный раздел).
5. Программа создаст файл с именем вида  
   `HospitalStatistics_backup_ГГГГ-ММ-ДД_ЧЧ-мм.db`  
   в выбранной папке.

Копия создаётся средствами SQLite (корректный снимок базы на момент операции). Не закрывайте приложение до появления сообщения об успехе.

**Рекомендации:** храните копии на **другом** носителе или компьютере, чем рабочая программа; периодически проверяйте, что файлы открываются и не нулевого размера.

## Восстановление из резервной копии (через программу)

1. В **«Справке»** откройте тему **«Резервное копирование БД»**.
2. Нажмите **«Восстановить БД»**.
3. Подтвердите предупреждение: **текущая база будет заменена** выбранным файлом.
4. Укажите файл резервной копии (`.db`), который вы ранее сохранили.
5. После успешного восстановления приложение **перезапустится** автоматически.

Пока идёт восстановление, не отключайте питание и не копируйте поверх файл базы вручную.

## Ручное копирование (без кнопок в программе)

Иногда удобно скопировать файл вручную (например, из проводника).

**Создать копию вручную:** полностью закройте приложение, скопируйте файл `HospitalStatistics.db` из каталога данных пользователя (пути см. выше) в безопасное место.

**Восстановить вручную:** закройте приложение, замените `HospitalStatistics.db` в том же каталоге данных своей сохранённой копией (предварительно можно переименовать текущий файл в `HospitalStatistics_old.db` на случай отката).

## Частые проблемы

| Ситуация | Что делать |
|----------|------------|
| «Файл уже используется» | Закройте все окна программы и повторите. Не открывайте `.db` в сторонних редакторах во время копирования. |
| Восстановили «не ту» копию | Если сохранили старый `HospitalStatistics.db` под другим именем — закройте программу и верните нужный файл вручную. |
| Файл не похож на базу SQLite | Убедитесь, что выбран именно файл резервной копии с расширением `.db`, созданный этой программой или корректной копией `HospitalStatistics.db`. |
| Резервная копия получилась **нулевого/очень малого размера** | Считайте копию недействительной. Создайте резервную копию ещё раз в другую папку/на другой носитель. Проверьте, что на диске достаточно свободного места. |
| Ошибка «Недостаточно места на диске» / копирование прерывается | Освободите место или выберите другой диск/папку. Не сохраняйте резервные копии в системные каталоги и на заполненный раздел. |
| Ошибка «Отказано в доступе» (нет прав на запись/чтение) | Выберите папку, где у вас есть права (например, «Документы»). На Windows при необходимости запустите программу от имени администратора или снимите ограничения на папку. |
| **Повреждён файл копии** (не открывается, ошибки при восстановлении) | Попробуйте другую копию. Храните несколько копий, периодически проверяйте их (файл не нулевой, корректно восстанавливается на тестовой машине). Не выдёргивайте флешку во время записи. |
| Резервная копия лежит на **облачном/сетевом диске** (OneDrive/сетевой ресурс) и восстановление даёт ошибки | Скопируйте файл копии **локально** на диск компьютера и восстановите из локальной папки. Облачная синхронизация/сетевые сбои могут портить или блокировать файл. |
| Антивирус/защитник блокирует файл `.db` или операцию копирования | Временно добавьте папку программы/папку с копиями в исключения антивируса или выполните копирование в другую папку. После успешного восстановления верните настройки защиты. |
| После восстановления программа запускается, но данные «странные»/часть записей пропала | Возможно, восстановлена копия не от нужной даты или копия была сделана уже после проблемы. Проверьте дату/время файла копии и попробуйте более раннюю/другую копию. |
| Восстановление из копии, сделанной **в другой версии программы**, вызывает ошибки | Обновите программу до версии, на которой делалась копия (или новее), затем повторите восстановление. Если проблема сохраняется — используйте другую копию и сообщите разработчику. |
