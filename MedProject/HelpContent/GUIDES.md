# Справочники

Раздел "Справочники" предназначен для управления базовыми данными системы: отделениями, типами коек и самими койками. Эти данные необходимы для работы с отчётами и вводом информации о движении пациентов.

## 1. Общая информация

В разделе "Справочники" есть три вкладки:

- **Отделения** – список всех отделений больницы
- **Койки** – список всех коек с их характеристиками
- **Типы коек** – список типов коек (например: "Терапевтические", "Хирургические")

**Важно:** Перед началом работы с вводом данных необходимо настроить все справочники.

## 2. Работа со списками (поиск, фильтры, добавление, изменение, удаление)

Во всех вкладках раздела "Справочники" используются одинаковые принципы работы со списками.

### 2.1. Поиск

Поиск доступен во всех справочниках - введите текст, и таблица автоматически отфильтруется.

### 2.2. Добавление записи

1. Откройте нужную вкладку (**Отделения**, **Типы коек** или **Койки**)
2. Нажмите **"Добавить запись"**
3. Заполните обязательные поля
4. Нажмите **"Сохранить"**

Если введённые данные не проходят проверку, система покажет ошибку (например, пустое или неуникальное название, некорректная дата, отрицательное значение).

### 2.3. Изменение записи

1. Найдите нужную строку (поиск/фильтры)
2. Нажмите **✏️ (Редактировать)**
3. Внесите изменения и нажмите **"Сохранить"**

### 2.4. Удаление записей запрещено (защита исторических данных)

В системе действует механизм защиты исторических данных: **справочные записи не удаляются физически**, чтобы:

- отчёты за прошлые периоды оставались воспроизводимыми (одни и те же исходные данные дают тот же результат);
- не возникали “провалы” в истории (например, пациент/движение/отчёт ссылается на справочник, а справочник исчез);
- исключить незаметную потерю данных из-за случайного удаления.

Что делать вместо удаления:

- **Для коек** — используйте поле **"Не используется с"** (это корректный способ “вывести из эксплуатации”, не теряя историю).
- **Для отделений и типов коек** — если элемент больше не нужен, оставьте его в справочнике для истории и не используйте в новых данных; при необходимости создайте новый элемент с корректным названием.

## 3. Отделения

### 3.1. Назначение

Отделения – это структурные подразделения больницы (например: "Терапевтическое отделение", "Хирургическое отделение", "Педиатрическое отделение").

### 3.2. Поля в таблице

В таблице отображается только одно поле:

- **Название отделения** – полное название отделения

### 3.3. Ограничения и проверки данных

- **Название отделения:**
  - Не может быть пустым
  - Должно содержать минимум 2 символа
  - Должно быть уникальным (нельзя создать два отделения с одинаковым названием)

## 4. Типы коек

### 4.1. Назначение

Типы коек – это классификация коек по их назначению (например: "Терапевтические", "Хирургические", "Педиатрические").

### 4.2. Поля в таблице

В таблице отображается одно поле:

- **Название типа койки** – название типа (например: "Терапевтические")

### 4.3. Ограничения и проверки данных

- **Название типа койки:**
  - Не может быть пустым
  - Должно содержать минимум 2 символа
  - Должно быть уникальным

## 5. Койки

### 5.1. Назначение

Койки – это конкретные записи о количестве коек определённого типа в определённом отделении с указанием плана использования.

### 5.2. Поля в таблице

В таблице отображаются следующие поля:

- **Тип койки** – название типа койки (выбирается из справочника типов коек)
- **Количество** – количество коек данного типа в отделении
- **Отделение** – название отделения (выбирается из справочника отделений)
- **Дата начала действия** – дата, с которой эта запись начинает действовать
- **Не используется с** – дата, с которой койки перестали использоваться (может быть пустым)
- **Месячный план** – плановое количество койко-дней в месяц для этих коек

### 5.3. Обязательные и необязательные поля

**Обязательные поля:**
- **Тип койки** – выберите из списка
- **Отделение** – выберите из списка
- **Количество** – введите число (0 или больше)
- **Дата начала действия** – выберите дату
- **Месячный план** – введите число (0 или больше)

**Необязательные поля:**
- **Не используется с** – дата, когда койки перестали использоваться (можно оставить пустым)

### 5.4. Ограничения и проверки данных

- **Тип койки:** олжен быть выбран из списка (не может быть пустым)

- **Отделение:** должно быть выбрано из списка (не может быть пустым)

- **Количество:**
  - Должно быть целым положительным числом
  - Не может быть отрицательным
  - Не может быть пустым

- **Дата начала действия:**
  - Должна быть указана
  - Если указана дата "Не используется с", то дата начала действия должна быть **раньше** даты прекращения использования

- **Не используется с:**
  - Может быть пустым (если койки ещё используются)
  - Если указана, должна быть **позже** даты начала действия

- **Месячный план:**
  - Должен быть целым положительным числом
  - Не может быть отрицательным
  - Не может быть пустым

- **Дополнительные ограничения:** нельзя создать две записи с одинаковыми значениями:


### 5.5. Поиск и фильтрация (особенности для коек)

Вкладка "Койки" поддерживает поиск по выбранной колонке (**Фильтровать по**) и стандартные флажки:

- **Текущий год** — койки с планом на этот год
- **Действующий план** — актуальные на сегодня планы коек 

**Пример:** Чтобы найти все койки в «Терапевтическом отделении»:
1. Выберите в «Фильтровать по» → **«Отделение»**
2. Введите в «Поиск» → **«Терапевтическое»**

**Пример:** Чтобы увидеть только актуальные на сегодня койки:
- Установите флажок **«Действующий план»**

## 6. Порядок настройки справочников

Рекомендуемый порядок настройки справочников:

1. Сначала добавьте отделения
2. Затем добавьте типы коек
3. В последнюю очередь добавьте койки

**Пример настройки:**

1. Отделения:
   - Терапевтическое отделение
   - Хирургическое отделение

2. Типы коек:
   - Терапевтические
   - Хирургические

3. Койки:
   - Терапевтическое отделение + Терапевтические (40 коек, план 1200 койко-дней)
   - Хирургическое отделение + Хирургические (30 коек, план 900 койко-дней)

## 7. Важные замечания

### 7.1. Дата начала действия

**Дата начала действия** позволяет вести историю изменений. Например:

- С 01.01.2024 в отделении было 30 коек
- С 01.06.2024 количество увеличилось до 40 коек

В этом случае создаются две записи:
- Первая: дата начала действия 01.01.2024, количество 30
- Вторая: дата начала действия 01.06.2024, количество 40

Система автоматически использует актуальную запись на нужную дату.

### 7.2. Поле "Не используется с"

Это поле позволяет отметить, что койки больше не используются, но данные о них сохраняются для истории.

**Как это работает:**

Поле "Не используется с" определяет, будут ли койки учитываться в отчётах:

- **Если поле пустое:** Койки считаются активными и учитываются во всех отчётах
- **Если указана дата:** Койки перестают учитываться в отчётах **после** указанной даты

**Логика включения в отчёты:**

1. **Койки включаются в отчёт, если:**
   - Поле "Не используется с" пустое (койки активны)
   - Дата "Не используется с" **позже** даты окончания отчётного периода (койки ещё использовались в этом периоде)
   - Дата "Не используется с" **внутри** отчётного периода (койки использовались в этом периоде, но перестали)

2. **Койки НЕ включаются в отчёт, если:**
   - Дата "Не используется с" **раньше** даты начала отчётного периода (койки перестали использоваться до начала периода)

**Примеры:**

- **Пример 1:** Отчёт за январь 2024 (01.01.2024 - 31.01.2024)
  - Койки с "Не используется с" = 15.02.2024 → **включаются** (ещё использовались в январе)
  - Койки с "Не используется с" = 15.01.2024 → **включаются** (использовались в январе)
  - Койки с "Не используется с" = 15.12.2023 → **не включаются** (перестали использоваться до января)

- **Пример 2:** Отчёт за весь 2024 год
  - Койки с "Не используется с" = 01.12.2024 → **включаются** (использовались в 2024 году)
  - Койки с "Не используется с" = 01.12.2023 → **не включаются** (перестали использоваться до 2024 года)

**Важно:** Поле "Не используется с" не удаляет запись о койках, а только исключает их из будущих отчётов. Исторические данные сохраняются.

### 7.3. Месячный план

**Месячный план** – это плановое количество койко-дней в месяц для данных коек. Используется для расчёта процента выполнения плана в отчётах.

**Пример расчёта:**
- Количество коек: 40
- Дней в месяце: 30
- План койко-дней: 40 × 30 = 1200

Но в системе вы вводите **месячный план** напрямую (например, 1200), а система сама рассчитывает дневной план при необходимости.

## 8. Частые ошибки и их решение

### Ошибка: "Нельзя удалить запись"

**Решение:** Удаление записей в справочниках запрещено (см. раздел **2.4**). Для коек используйте **"Не используется с"**, для прочих справочников — оставляйте элемент для истории и создавайте новый при необходимости.

### Ошибка: "Дата начала действия должна быть раньше даты прекращения использования"

**Решение:** Проверьте, что дата в поле "Не используется с" позже даты начала действия.

### Ошибка: "Запись с такими же значениями уже существует"

**Решение:** Измените хотя бы одно из полей: отделение, тип койки, количество, дата начала действия или месячный план.

### Ошибка: "Количество не может быть отрицательным"

**Решение:** Введите положительное число или 0.

## 9. Советы по работе

1. **Используйте поиск** – при большом количестве записей поиск поможет быстро найти нужную
2. **Не пытайтесь удалять записи** – исторические данные защищены от удаления; для коек используйте "Не используется с"
3. **Ведите историю изменений** – создавайте новые записи с новой датой начала действия вместо редактирования старых

Успешной работы со справочниками!
