# Быстрый старт

Добро пожаловать в систему **«Коечный учёт»**! Это приложение предназначено для ежедневного учёта движения пациентов в стационаре и формирования статистических отчётов.

## 1. Описание приложения

Система «Коечный учёт» позволяет:

- **Вводить данные** о движении пациентов по каждому типу коек за каждый день
- **Управлять справочниками** (отделения, койки, типы коек)
- **Формировать PDF-отчёты** о движении пациентов и работе коечного фонда
- **Просматривать справку** по всем разделам системы прямо в приложении

## 2. Требования к системе

Для работы приложения необходимо:

- **Операционная система:** Windows 10 или выше
- **База данных:** SQLite — файл `HospitalStatistics.db` создаётся **автоматически** рядом с исполняемым файлом, никаких дополнительных серверов не требуется
- **Просмотр отчётов:** любая программа для открытия PDF-файлов (например, Adobe Acrobat Reader)
- **Разрешение экрана:** минимум 1280×720 пикселей (рекомендуется 1920×1080)

## 3. Запуск приложения

1. **Дважды щёлкните** по файлу запуска приложения (`MedProject.exe`)
2. Дождитесь загрузки — при первом запуске это может занять несколько секунд
3. Приложение откроется и по умолчанию отобразит раздел **«Ввод данных»**

**При первом запуске приложение автоматически:**
- Создаст файл базы данных `HospitalStatistics.db`
- Заполнит базовые справочники начальными данными (типы коек, отделения, койки)

> **Важно:** Файл базы данных создаётся в той же папке, откуда запущено приложение. Не удаляйте этот файл — в нём хранятся все введённые данные.

## 4. Обзор интерфейса

Главное окно состоит из двух частей:

### 4.1. Панель навигации (слева)

Тёмная боковая панель с кнопками для перехода между разделами:

| Раздел | Горячая клавиша | Назначение |
|--------|----------------|------------|
| **Ввод данных** | Ctrl+1 | Основная рабочая область: ввод ежедневных данных о пациентах |
| **Справочники** | Ctrl+2 | Управление отделениями, койками и типами коек |
| **Справка** | Ctrl+3 | Документация и руководство пользователя |

### 4.2. Рабочая область (справа)

Здесь отображается содержимое выбранного раздела. При запуске автоматически открывается раздел **«Ввод данных»**.

## 5. Основные разделы

### 5.1. Ввод данных

**Назначение:** Ежедневный ввод данных о движении пациентов.

**Что можно делать:**
- Выбрать отделение из выпадающего списка
- Выбрать дату (по умолчанию — сегодня)
- Заполнить таблицу по каждому типу коек
- Сохранить данные за день (Ctrl+S)
- Просмотреть и отредактировать ранее введённые данные
- Сформировать PDF-отчёты за любой период

**Основные поля для ввода:**
- Состояло на начало суток
- Поступило всего / сельских / детей до 14 лет
- Переведено из / в другие отделения
- Выписано всего / в т.ч. в другие стационары
- Умерло
- Состоит матерей при детях / выписано матерей

Подробнее — в разделе справки **«Ввод данных»**.

### 5.2. Справочники

**Назначение:** Управление базовыми данными системы.

**Вкладки справочников:**

1. **Отделения** — добавление, редактирование, удаление отделений
2. **Койки** — управление койками с привязкой к отделению и типу коек, указанием количества, плана и дат
3. **Типы коек** — добавление и редактирование типов коек

**Основные действия:**
- Нажмите **«Добавить»** или **Ctrl+N** — создать новую запись
- Выберите строку и нажмите **«Изменить»** или **F2** — редактировать запись
- Выберите строку и нажмите **«Удалить»** или **Delete** — удалить запись (с подтверждением)

Подробнее — в разделе справки **«Справочники»**.

### 5.3. Справка

**Назначение:** Документация и руководство пользователя.

Доступные темы справки:
- **Быстрый старт** (этот раздел)
- **Горячие клавиши** — полный список сочетаний клавиш
- **Ввод данных** — описание всех колонок таблицы, правил валидации и межсуточных проверок
- **Справочники** — подробное описание работы с отделениями, койками и типами коек
- **Отчёт №1: Движение больных** — описание расчётов первого отчёта
- **Отчёт №2: Работа коек** — описание расчётов второго отчёта
- **Логирование** — настройка и архивирование журналов работы приложения

## 6. Первые шаги

### Шаг 1: Настройка справочников

При первом запуске база уже содержит начальные данные. Вы можете дополнить или скорректировать их:

1. Перейдите в раздел **«Справочники»** (Ctrl+2)
2. На вкладке **«Типы коек»** проверьте список типов и при необходимости добавьте новые
3. На вкладке **«Отделения»** добавьте отделения вашей больницы
4. На вкладке **«Койки»** добавьте койки, указав для каждой:
   - Отделение
   - Тип койки
   - Количество коек
   - Месячный план койко-дней
   - Дату начала действия записи

### Шаг 2: Ввод данных за день

После настройки справочников начните вводить ежедневные данные:

1. Перейдите в раздел **«Ввод данных»** (Ctrl+1)
2. В верхней части выберите **отделение** из выпадающего списка
3. Убедитесь, что в поле даты установлен нужный день (по умолчанию — сегодня)
4. Для каждой строки (типа коек) заполните нужные поля
5. Проверьте, нет ли ячеек с красной рамкой — они указывают на ошибки валидации
6. Нажмите кнопку **«Сохранить данные»** или **Ctrl+S**
7. При необходимости переключитесь на другое отделение и повторите

> **Важно:** Система автоматически проверяет корректность данных и показывает ошибки в подсказках при наведении на ячейку с красной рамкой. Сохранение заблокировано до устранения всех ошибок.

### Шаг 3: Формирование отчётов

После ввода данных за нужный период сформируйте PDF-отчёт:

1. В разделе **«Ввод данных»** нажмите одну из кнопок в нижней части экрана:
   - **«Отчёт — движение больных»** (Ctrl+R) — отчёт №1
   - **«Отчёт — работа коек»** (Ctrl+Shift+R) — отчёт №2
2. В открывшемся окне укажите **начальную** и **конечную** даты периода
3. Нажмите **«Сформировать отчёт»**
4. После формирования PDF-файл автоматически откроется в программе просмотра

## 7. Важные правила

### 7.1. Межсуточная связь

Количество пациентов на начало текущего дня должно совпадать с количеством пациентов на конец предыдущего дня:

```
Состояло на начало суток (сегодня) = Состоит всего (вчера)
```

Система автоматически проверяет это правило. При несоответствии ячейка выделяется красной рамкой с подсказкой.

### 7.2. Ограничения по количеству пациентов

- **«Состояло на начало суток»** не может превышать количество коек данного типа в отделении
- Частичные показатели не могут превышать общие (например, «Поступило сельских» ≤ «Всего поступило»)

### 7.3. Логические проверки

Система проверяет, что:
- «Умерло» и «Выписано» не превышают «Состояло на начало суток»
- «Состоит сельских» не превышает «Состоит всего»
- «Выписано в другие стационары» не превышает «Всего выписано»

## 8. Советы по работе

1. **Вводите данные ежедневно** — это поможет избежать накопления работы и ошибок в межсуточных проверках
2. **Проверяйте красные ячейки** — наведите курсор для просмотра подсказки с описанием ошибки
3. **Используйте горячие клавиши** — Ctrl+S для сохранения, Ctrl+N для добавления, F2 для редактирования
4. **Не удаляйте файл базы данных** `HospitalStatistics.db` — в нём хранятся все ваши данные

Доступные темы:
